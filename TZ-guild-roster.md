# Міні-ТЗ: веб-ростер гільдії (WWM, режим 30×30)

## Мова проєкту
**Всі написи в інтерфейсі — лише українською або англійською.**
Російська мова не використовується ні в UI-мітках, ні в коментарях коду, ні в даних.
- Назви білдів — англійські (відповідають назвам у грі).
- Системні написи, кнопки, підказки, заголовки — українською.
- Коментарі в коді — українською.

## Мета
Одностраничное статическое веб-приложение для учёта игроков гильдии и их билдов.
Деплой — GitHub Pages. Без бэкенда, без баз данных, без регистрации для зрителей.

## Стек
- Чистый статический проект: один `index.html` + (опционально) `style.css`, `app.js`, `data.js`.
- Без сборщиков и фреймворков (или лёгкий Vanilla JS). Цель — чтобы открывалось мгновенно и хостилось на GitHub Pages без CI-сборки.
- Адаптивная вёрстка: основной сценарий просмотра — мобильный (Discord открывают с телефона).

## Модель данных
Данные игроков — в отдельном файле `data.js` (или JSON-объект в начале `app.js`),
чтобы редактировал только владелец и обновлял через git push.

Структура записи игрока:
```
{
  name: "string",          // игровое имя
  build: "string",         // ключ билда из BUILDS
  altBuild: "string|null", // ключ альт-билда из BUILDS, либо null
  gearLevel: number,       // уровень шмота (число)
  ready: boolean,          // готов на бой 30х30
  note: "string"           // тактическая заметка: "фокус", "фланг", "защита точки" и т.п.
}
```

## Конфиг билдов (ВЫНЕСТИ ОТДЕЛЬНО, легко редактируемый)
Объект `BUILDS` — единственное место, где задаются билды и их цвета.
Владелец меняет здесь — список фильтров, легенда и цветовая кодировка обновляются автоматически.
```
const BUILDS = {
  tank:    { label: "Танк",        color: "#3b82f6" },
  healer:  { label: "Хилер",       color: "#22c55e" },
  melee:   { label: "Ближний ДД",  color: "#ef4444" },
  ranged:  { label: "Дальний ДД",  color: "#f59e0b" },
  support: { label: "Саппорт",     color: "#a855f7" }
};
```
(Это значения по умолчанию — владелец заменит на реальные билды гильдии.)

## Функциональность (для всех зрителей, без авторизации)

### Режимы просмотра (переключатель)
1. **Полный список** — все игроки, плоская таблица/карточки.
2. **Группировка по билдам** — секции по основному билду, в шапке секции счётчик игроков.
3. **Состав на бой** — только игроки с `ready: true`, сгруппированы по билду; вверху сводка «сколько кого готово».

### Фильтры (применяются к любому режиму)
- По основному билду (мультивыбор).
- По альт-билду (мультивыбор).
- По уровню шмота — диапазон (мин/макс, слайдер или два поля).
- По `ready` — переключатель «только готовые».
- Поиск по имени (живой, по подстроке, регистронезависимый).
- Кнопка «Сбросить фильтры».

### Цветовая кодировка
- Бейдж билда красится в `color` из `BUILDS`.
- Альт-билд — тем же цветом, визуально вторичный (контур/полупрозрачность).
- Легенда цветов всегда видна (можно сворачивать на мобиле).

### Сортировка
- По имени, по уровню шмота (возр./убыв.), по билду. Клик по заголовку колонки / селект на мобиле.

## Мини-авторизация для администрации (опционально, низкий приоритет)
ВАЖНО: статический сайт не обеспечивает реальной защиты — пароль в клиентском коде
виден в исходнике. Поэтому:
- Не хранить ничего секретного.
- «Админ-режим» = чисто косметический гейт (простой пароль в localStorage),
  который лишь показывает/прячет вспомогательный экспортный блок.
- Реального редактирования через UI НЕТ — данные правятся в `data.js` через git.
- Если эта фича усложняет проект — пропустить полностью. Основная ценность —
  read-only ростер с фильтрами.

## Нефункциональные требования
- Открывается по прямой ссылке GitHub Pages, без логина, без скачиваний.
- Не светит никаких данных автора/владельца (это просто статика на GitHub Pages —
  имя репозитория видно, но не привязано к личности, если репозиторий назван нейтрально).
- Быстрая загрузка, работает офлайн после первого открытия (опционально: простой кэш).
- Тёмная тема по умолчанию (игровая аудитория, Discord-контекст).

## Структура репозитория
```
/index.html
/style.css        (опц.)
/app.js
/data.js          ← владелец редактирует игроков здесь
/README.md        ← как обновлять ростер и как деплоить на Pages
```

## Деплой
GitHub Pages из ветки `main`, папка `/root`. README должен содержать пошагово:
1. как добавить/изменить игрока в `data.js`,
2. как поменять билды/цвета в `BUILDS`,
3. как закоммитить и запушить (обновление сайта),
4. ссылка вида `https://<user>.github.io/<repo>/`.

## Приоритеты (если время ограничено)
1. Модель данных + конфиг билдов.
2. Полный список + цветовая кодировка + легенда.
3. Фильтры (билд, уровень шмота, поиск по имени).
4. Режимы «группировка по билдам» и «состав на бой».
5. Сортировка.
6. Мини-админ-гейт (по желанию, можно опустить).
